# Domain docs

This repo uses a single-context layout:
- `GLOSSARY.md` at the repo root.
- Architecture decision records in `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If they are absent, proceed silently; domain-modeling creates them
when terms or decisions are resolved.

Use glossary terms consistently in issues, proposals, and tests.
Note terminology gaps for domain-modeling.

If a proposal contradicts an ADR, identify the conflict explicitly
and explain why the decision should be reconsidered.
